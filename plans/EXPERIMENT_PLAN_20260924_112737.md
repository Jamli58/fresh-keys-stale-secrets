# Experiment Plan

**Problem**: SMEs send prompts containing confidential business numbers (prices, unit costs, volumes, margins) to cloud LLMs. The existing ways to disguise numbers in LLM prompts have never been tested against an attacker that combines numeric structure with the LLM's own world knowledge. Those defenses are value substitution that keeps order (Zhang et al., AAAI'26), metric-DP noise (Prεεmpt, NDSS'26) and shared scaling.
**Method Thesis**: Semantic priors that an LLM infers from the prompt's prose (sector, product, scale, locale) let an honest-but-curious provider recover confidential quantities from disguised prompts noticeably better than classical attacks that have the same numeric information. Key reuse across queries makes this worse.
**Date**: 2026-09-24
**Scope**: Pilot. This plan measures *leakage*, not a new defense. Its result decides the attack/C4 section and whether the G2 theory (invariant leakage) is worth building. See `research-wiki/gap_map.md` G2 and the novelty check trace (`.aris/traces/novelty-check/2026-09-24_run01/`).

## Threat Model (fixed before running)

- **Adversary**: honest-but-curious cloud LLM provider. It sees every disguised prompt and knows each defense's *algorithm*, but not its keys or randomness (Kerckhoffs).
- **Auxiliary knowledge**: a public sector-level prior table P_pub (P10 / Q25 / median / Q75 / P90 of price, unit cost and margin per sector and product class), plus whatever the attacker LLM already knows.
- **Targets**:
  - T1: gross margin (p−c)/p per product.
  - T2: unit cost c.
  - T3: the key itself (for scaling / offset-type defenses).
  - T4: rank order of products by margin. Secondary.

## Prerequisite for C1 (M0.5): cues beyond sector and class

Found while retargeting C1: the M0 prompts carry no cue beyond sector and product class, and A1+ is given both. C1 could therefore not be positive **by construction**. Before M2, the generator and templates must add realistic cues whose link to prices is *real-world knowledge*, not a rule the attacker could decode.
- **City:** each firm gets a real city drawn from a fixed list. The firm's latent location price level is set from that city's **public cost-of-living / price-level index** (source to be cited), plus firm-level noise, so the city is a noisy real-world signal of the price level.
- **Positioning:** premium, standard or discount, stated in the prose (e.g. "we use organic, locally sourced flour" vs "no-frills, high-volume"). It is sampled from the firm's latent price level and efficiency through a documented noisy mapping (e.g. an ordered-logit model).
- **Unchanged:** P_pub stays broken down by sector × class only, and never by city or positioning.
- **Anti-circularity:** the mapping from latent variables to cues is fixed before M2, logged in the contract, never shown to attackers, and never tuned on attacker results. B3's cue-stripped control removes the city and positioning as well.
- **Gate:** re-run R001 and R005 with the new cues, and re-run M1 (A0/A1/A1+) so the classical baselines see the same prompts.

## Data: Counterfactual SME Business Records

- **Generator**: 6 sectors (bakery/café, machine shop, apparel e-commerce, IT consulting, construction subcontractor, specialty retail). Each firm has 3–8 products with price, unit cost, monthly volume, overhead and 12 months of sales.
- **Generator prior P_gen ≠ attacker prior P_pub** (addresses anti-claim (c)):
  - Values come from a latent firm-level model: firm efficiency factor, location price level, product mix, heavy tails.
  - P_pub is computed only from *aggregate summaries* of a separate held-out generator draw, mimicking published statistics.
  - Real-world anchoring of P_gen comes from public sector aggregates, chosen once and documented. It is not tuned to help or hurt either attacker.
- **Strata**:
  - *Typical*: 80%.
  - *Atypical*: ~20%, defined as firm median margin outside the sector's P10–P90 band. (Corrected 2026-09-24 after R001: the original "outside the IQR" rule labels ~50% of firms atypical by construction.) This tests reliance on the prior.
- **Counterfactual guarantee**: fictional firm and product names, and no real addresses. A prose-only probe (no numbers) checks that attacker LLMs do no better than P_pub on names alone, which shows the firms can't be looked up or memorized.
- **Prompts**:
  - 5 SME task templates: quote pricing, margin review, break-even, monthly sales summary, supplier comparison.
  - Each is paraphrased 3× by a local model to vary the prose.
  - Prose carries realistic sector cues; a **cue-stripped** variant removes them (used in B3).
- **Pilot size**: 300 firms × 2 tasks = 600 base prompts; 60 firms × 16-query sequences for key reuse (B2).
- **Splits**: 50 firms are a dev split for tuning attacker prompts and hyperparameters. The remaining 250 are the test split, touched once.

## Defenses (reimplemented; no public code for D3 or D4)

| ID | Defense | Specification | Key regime |
|----|---------|---------------|-----------|
| D0 | None | Plaintext numbers | Upper bound on leakage |
| D1 | Shared scaling | All monetary fields × secret k ~ LogUniform[0.1, 10]; counts unchanged | Fresh per prompt / reused per firm |
| D1' | Per-field scaling (control) | Independent k_i per field | Shows that removing shared keys removes the margin invariant (C2) |
| D2 | Zhang et al. AAAI'26 | As described in 2504.00299v2 §Method: years shifted by one offset (differences kept); special numbers (month-end days) kept; all other numbers binned into intervals and mapped to random values in a target range *keeping order*; topic shifted by a local LLM. Mapping h kept locally | Fresh h per prompt / h reused per firm |
| D3 | Prεεmpt metric-DP | ℓ1 exponential mechanism (Alg. 3 of 2504.05147v2), per-token budget ε/t; ε ∈ {0.5, 1, 2} (the paper also uses 0.1) | Fresh randomness per prompt (no key to reuse; B2 measures averaging of repeated noisy releases instead) |

## Attackers (all told how the defense works)

| ID | Attacker | Information used |
|----|----------|------------------|
| A0 | Prior-only guess | P_pub median for the sector (sector from oracle). Floor used to compute "advantage" |
| A1 | Classical Bayesian | Transformed numbers + field types + P_pub (**sector unknown** → mixture prior) + algebraic constraints (p > c, totals add up, order constraints for D2), then MAP/posterior mean. Includes range attack, distribution matching (log-space alignment for D1; quantile/order matching for D2, in the style of OPE inference attacks) and posterior shrinkage for D3 |
| A1+ | Classical Bayesian + oracle sector | Same as A1 with the true sector given. **The fair control for C1** |
| A2 | LLM prose-only | Attacker LLM reads the disguised prompt with all numbers masked, and outputs point estimates plus 80% intervals for T1/T2 |
| A3 | LLM end-to-end | Attacker LLM reads the full disguised prompt (numbers included) plus a description of the defense algorithm |
| A4 | Hybrid (LLM prior → Bayesian) | LLM pulls sector, product class, scale and locale from the prose, producing a per-prompt prior that feeds the A1 solver. Expected strongest; also the **simplicity check** against A3 |

**Attacker LLMs**:
- 2 open-weight models (one ~8B, one ~30–70B class) served locally with vLLM, temperature 0.
- One frontier API model on a 150-prompt subset (the data is counterfactual, so it's safe to send).
- Attacker prompts are tuned **on dev only**, with a capped budget of 10 prompt variants per attacker.

## Metrics

- **Decisive**:
  - T1 margin: hit rate within ±2 pp and ±5 pp; MAE in pp.
  - T2 unit cost: hit rate within ±10%; median relative error.
  - **Advantage** = hit rate(attack) − hit rate(A0).
  - C1 test statistic: Δ = A4 − A1+.
- **Secondary**:
  - T3 key relative error / exact recovery.
  - T4 Kendall τ.
  - Calibration: coverage of the 80% intervals (A2–A4).
  - Performance per stratum: typical vs atypical.
- **Statistics**:
  - Bootstrap over firms (10k resamples), 95% CI.
  - Paired comparisons on the same prompts.
  - 3 seeds for defense randomness (keys / noise); LLM decoding is deterministic.

## Experiment Blocks

### Block 1: Attack Matrix, Fresh Keys (main anchor)
- **Claim tested**: C1 (headline), C2 (the D1 margin invariant).
- **Why this block exists**: the main table, showing how much each defense leaks to each attacker.
- **Dataset / split / task**: test split, 500 prompts (250 firms × 2 tasks), typical and atypical strata pooled and reported separately.
- **Compared systems**: D0, D1, D1', D2, D3 (3 ε values) × A0, A1, A1+, A2, A3, A4.
- **Metrics**: T1/T2 hit rates, advantage over A0, Δ = A4 − A1+.
- **Setup details**: fresh key or noise per prompt; 3 defense seeds; open LLMs on all prompts, API model on a 150-prompt subset.
- **Success criterion**:
  - Δ > 0 with CI excluding 0 on ≥2 of {D1, D2, D3@ε=1}, for ≥2 attacker LLMs.
  - D1 margin MAE ≈ 0 for every attacker (sanity check).
  - D1' margin advantage drops towards A0 levels.
- **Failure interpretation**: if Δ ≈ 0, knowing the sector explains the LLM's advantage. The attack story then becomes "hide the sector", or the paper pivots to theory and defense (G1/G2), with classical attacks as the threat model.
- **Table / figure target**: Table 1 (defense × attacker, advantage ± CI).
- **Priority**: MUST-RUN.

### Block 2: Key Reuse / Cross-Query Linkage
- **Claim tested**: C2.
- **Why this block exists**: the novelty review and Wang et al. both flag key reuse. It needs to be quantified for LLM sessions, where reuse is the natural default.
- **Dataset / split / task**: 60 test firms × 16-query sequences with mixed task templates.
- **Compared systems**: D1 and D2 with reused key or h, vs. a fresh-key reference. D3 under repeated releases (noise averaging). Attackers A1+ and A4 (the two strongest from B1).
- **Metrics**: T2 hit rate and T3 key error vs. n ∈ {1, 2, 4, 8, 16}.
- **Setup details**: the attacker links queries by firm (worst case: the provider sees the account).
- **Success criterion**: recovery rises clearly with n under reuse, e.g., D1 key recovered within ±5% by n ≤ 4 for most firms, while fresh keys stay flat.
- **Failure interpretation**: if reuse adds little, per-prompt keys are already easy to break (report that) or the defense is robust to linkage (a weaker C2).
- **Table / figure target**: Figure 2 (recovery vs n, one line per defense × regime).
- **Priority**: MUST-RUN.

### Block 3: Where Does the LLM Advantage Come From? (novelty isolation + frontier necessity)
- **Claim tested**: C1. Rules out anti-claim (b) and shows whether the LLM is necessary.
- **Why this block exists**: reviewers will say "that's just a sector prior." This block breaks the gain down.
- **Dataset / split / task**: the B1 test prompts under D1 and D2 (plus D3@ε=1 if B1 shows gains there).
- **Compared systems** (information-matched ladder):
  1. A1 (numbers only, sector unknown).
  2. A1+ (numbers + oracle sector).
  3. A1 + **LLM-extracted sector label only**.
  4. A4 full (LLM-extracted rich prior: sector + product class + scale + locale).
  5. A4 on **cue-stripped prose**.
  6. A2 prose-only.
  7. A3 end-to-end.
- **Metrics**: T1/T2 hit rate, and each step's increment on the ladder.
- **Setup details**: same prompts, keys and seeds as B1; the two open LLMs.
- **Success criterion**: A4 full > A1+ (the LLM adds more than the sector label), and A4 on cue-stripped prose falls back towards A1 (the gain comes from the prose cues).
- **Failure interpretation**:
  - If rung 3 ≈ rung 4: the LLM adds only sector classification. Report that as a finding; it still matters for defenses, which must hide the sector.
  - If A3 > A4: an end-to-end LLM beats the modular hybrid. Report it, and note the simplicity trade-off.
- **Table / figure target**: Table 2 (ladder), or Figure 3 (stacked increments).
- **Priority**: MUST-RUN.

### Block 5: Does Zhang et al.'s topic shift remove the prose channel? (C1c)
- **Claim tested:** C1c. Under D2 the numbers carry almost no per-product margin information (R010b), so this block isolates the prose.
- **Dataset / split / task:** B1 test prompts under D2. Three variants: (i) cued prose, (ii) cued prose after the Zhang et al. topic shift (local LLM, per A-D2-5), (iii) cue-stripped prose.
- **Compared systems:** A0, A1+, A2 (prose only), A4.
- **Metrics:** unit-cost hit@±10%, margin hit@±5pp, and the advantage over A0.
- **Success criterion:** two-sided and reported either way. The difference in advantage between (i) and (ii), with its CI, is the finding.
- **Failure interpretation:** if (i) itself shows no advantage, the prose carries no usable prior even before the topic shift. C1c is then uninformative, and the realism of the cues should be checked.
- **Table / figure target:** Table 3.
- **Priority:** MUST-RUN (cheap: reuses the B1 attacker outputs, plus one topic-shift pass).

### Block 4: Memorization & Prior Robustness
- **Claim tested**: rules out anti-claims (a) and (c).
- **Why this block exists**: reviewers will ask whether the LLM is memorizing firms or benefiting from matched generator and attacker priors.
- **Dataset / split / task**:
  - (i) Prose-only probe with names only (no numbers) on the counterfactual firms.
  - (ii) Typical vs atypical strata (from B1).
  - (iii) Corrupted-prior sweep: P_pub scaled by {0.7, 0.85, 1.15, 1.3}.
  - (iv) *Nice-to-have*: ~50 real public small-cap firms from published filings as a memorization control, clearly separated.
- **Compared systems**: A1+, A4 (and A0 for the floor).
- **Metrics**: advantage per condition; calibration coverage.
- **Success criterion**:
  - (i) The probe gives ≈ A0 advantage (no memorization).
  - (ii) A4's advantage shrinks on atypical firms but stays > 0.
  - (iii) A4 degrades gracefully; report the crossover point where A4 < A1.
- **Failure interpretation**: a large probe advantage means the counterfactual generator leaks through names or prose (fix the generator). A collapse under a slightly wrong prior means the attack is fragile: report its limits.
- **Table / figure target**: Appendix Table A1, Figure A1.
- **Priority**: MUST-RUN for (i)–(ii), which are cheap and reuse B1 outputs. NICE-TO-HAVE for (iii)–(iv).

## Compute and Data Budget
- **Total estimated GPU-hours**: ~20–30 A100-hours for the open-weight attackers (vLLM, batched). The 8B model is ~5× cheaper; a single 24–48GB GPU is enough if the large model is ≤32B or quantized. These are estimates, not measurements; R011 records actual throughput.
- **API**: frontier attacker on ≈150 prompts × 5 defense configurations × 3 attacker modes ≈ 2.3k calls, plus the B2 subset. Low cost; confirm pricing before running.
- **Data preparation needs**: the generator and P_pub table (the largest human effort, ~2–3 days). Five task templates × 3 paraphrases. Reimplementations of D2 and D3.
- **Human evaluation needs**: none for the metrics, which are numeric ground truth. A 50-prompt manual spot check that the paraphrases are realistic and the topic shifts are faithful.
- **Biggest bottleneck**: faithful reimplementation of D2 (Zhang et al.) with no released code. Contacting the authors for code or parameters would lower the risk.

## Risks and Mitigations
- **Generator prior mismatch hides or exaggerates the LLM's gain** → Keep P_gen and P_pub separate, and report the atypical stratum and corrupted-prior sweep. State the P_gen sources in the appendix.
- **Unfair baseline tuning** (the LLM prompt gets more attention than the classical attacker) → Same dev budget for both; tune A1/A1+ first (M1) and freeze them before M2.
- **The D2 topic shift removes the prose cues, so the LLM gain on D2 is small** → That's a legitimate finding: topic shifting is a partial defense. B3's cue-stripped arm makes it interpretable. Report D2 with and without the topic shift as a sub-ablation if time allows.
- **Leakage metric mismatch with the prior papers** (Zhang et al. used an LLM judge; here it's numeric recovery) → Note it explicitly as a deliberate change of threat model, not a contradiction of their results.
- **Ethics** → All data counterfactual. The optional real-firm control uses only published filings, with results aggregated.
